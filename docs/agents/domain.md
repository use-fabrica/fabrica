# Domain Docs

Before exploring, read the root `GLOSSARY-MAP.md` and each glossary relevant to the task. Read relevant repo-wide ADRs in `docs/adr/` and context-specific ADRs at the paths in the map.

Proceed if a glossary or ADR directory is absent. `/domain-modeling` creates them when a term or decision is ready to record.

Use glossary terms in tickets, proposals, hypotheses, and tests. Note real vocabulary gaps for `/domain-modeling`. If a proposal contradicts an ADR, name the ADR and explain why it may be worth reopening.
